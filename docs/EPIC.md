# RhythmTrade - Epic & Story 拆分

> 按依赖关系排序，Epic 1 是地基，必须先完成

---

## Epic 0: 项目基础设施

**目标**：搭建可运行的项目骨架，配置好开发和部署环境

**验收标准**：
- 本地 `npm run dev` 能跑起来
- 推送到 GitHub 后 Vercel 自动部署
- 访问 Vercel 域名能看到页面

### Stories

| ID | Story | 描述 | 优先级 |
|----|-------|------|--------|
| E0-S1 | 初始化项目结构 | React + TypeScript + Rspack 基础配置 | P0 |
| E0-S2 | 配置 TailwindCSS | 安装配置 Tailwind，验证样式生效 | P0 |
| E0-S3 | 配置 Vercel 部署 | 连接 GitHub，配置自动部署 | P0 |
| E0-S4 | 配置路由 | 安装 react-router-dom，搭建基础路由结构 | P0 |
| E0-S5 | 配置 ESLint + Prettier | 代码规范统一 | P1 |

---

## Epic 1: 飞书 OAuth 集成

**目标**：用户可以通过飞书账号登录，获取操作文档的权限

**验收标准**：
- 点击「飞书登录」跳转飞书授权页
- 授权后回调到应用，获取并存储 access_token
- 能用 token 调通飞书 API（比如获取用户信息）

**依赖**：Epic 0

### Stories

| ID | Story | 描述 | 优先级 |
|----|-------|------|--------|
| E1-S1 | 创建飞书应用 | 在飞书开放平台创建应用，配置权限和回调地址 | P0 |
| E1-S2 | 实现 OAuth 跳转 | 前端构造授权 URL，跳转飞书授权页 | P0 |
| E1-S3 | 实现 Token 交换 | Vercel Serverless Function 换取 access_token | P0 |
| E1-S4 | Token 存储与刷新 | 前端存储 token，检测过期，自动刷新 | P0 |
| E1-S5 | 登录状态管理 | React Context 管理用户登录态 | P0 |
| E1-S6 | 登出功能 | 清除 token，重置状态 | P1 |

---

## Epic 2: 飞书文档操作

**目标**：能够在用户的飞书空间创建、读取、写入文档

**验收标准**：
- 自动创建 `RhythmTrade` 文件夹（如不存在）
- 能创建周报文档
- 能读取文档内容
- 能向文档追加 Block

**依赖**：Epic 1

### Stories

| ID | Story | 描述 | 优先级 |
|----|-------|------|--------|
| E2-S1 | 封装飞书 API Client | 统一的 API 调用层，处理 token 和错误 | P0 |
| E2-S2 | 文件夹管理 | 检查/创建 RhythmTrade 根文件夹 | P0 |
| E2-S3 | 周报文档创建 | 根据周数创建文档，初始化模板结构 | P0 |
| E2-S4 | 周报文档查询 | 列出所有周报，找到当前周的文档 | P0 |
| E2-S5 | 文档内容读取 | 读取文档 Block 列表，解析为结构化数据 | P0 |
| E2-S6 | 文档内容写入 | 向文档追加/更新 Block | P0 |

---

## Epic 3: 交易计划 CRUD

**目标**：用户可以创建、查看、编辑交易计划

**验收标准**：
- 能新建交易计划（填写表单，写入飞书文档）
- 能查看本周所有计划列表
- 能编辑已有计划
- 能更新计划状态（计划中→已开仓→已平仓）

**依赖**：Epic 2

### Stories

| ID | Story | 描述 | 优先级 |
|----|-------|------|--------|
| E3-S1 | 定义计划数据结构 | TypeScript 类型定义，飞书 Block 映射 | P0 |
| E3-S2 | 新建计划表单 | 表单 UI，字段校验 | P0 |
| E3-S3 | 计划写入飞书 | 将表单数据转为 Block 写入文档 | P0 |
| E3-S4 | 计划列表页面 | 读取本周文档，展示计划卡片列表 | P0 |
| E3-S5 | 计划详情页面 | 查看单个计划详情 | P0 |
| E3-S6 | 计划编辑功能 | 修改计划内容，更新飞书文档 | P1 |
| E3-S7 | 状态流转 | 计划中→已开仓→已平仓 状态更新 | P0 |
| E3-S8 | 跨周持仓处理 | 读取上周未平仓计划，显示在本周 | P1 |

---

## Epic 4: 复盘功能

**目标**：平仓后强制复盘，记录交易结果和反思

**验收标准**：
- 平仓时弹出复盘表单
- 必须填写复盘内容才能完成平仓
- 复盘内容写入飞书文档对应位置

**依赖**：Epic 3

### Stories

| ID | Story | 描述 | 优先级 |
|----|-------|------|--------|
| E4-S1 | 复盘表单设计 | 实际出场价、盈亏、执行评分、复盘笔记 | P0 |
| E4-S2 | 平仓流程集成 | 点击平仓时弹出复盘表单 | P0 |
| E4-S3 | 复盘数据写入 | 更新飞书文档中的计划 Block | P0 |
| E4-S4 | 复盘内容展示 | 在计划详情页展示复盘信息 | P0 |

---

## Epic 5: 周度统计与总结

**目标**：自动统计本周交易数据，支持手动填写周总结

**验收标准**：
- 周报页面顶部显示本周统计（交易次数、胜率等）
- 能手动填写本周总结
- 总结内容保存到飞书文档

**依赖**：Epic 4

### Stories

| ID | Story | 描述 | 优先级 |
|----|-------|------|--------|
| E5-S1 | 统计数据计算 | 根据计划列表计算交易次数、胜率、盈亏 | P0 |
| E5-S2 | 统计卡片 UI | 周报页面顶部展示统计数据 | P0 |
| E5-S3 | 周总结表单 | 手动填写本周复盘总结 | P0 |
| E5-S4 | 周总结存储 | 将总结写入飞书文档末尾 | P0 |

---

## Epic 6: 首页与引导

**目标**：打磨用户首次使用体验

**验收标准**：
- 未登录用户看到产品介绍和登录入口
- 已登录用户自动跳转到当前周报
- 首次使用有简单引导

**依赖**：Epic 1-5 基本完成

### Stories

| ID | Story | 描述 | 优先级 |
|----|-------|------|--------|
| E6-S1 | Landing Page | 产品介绍、核心价值、登录按钮 | P1 |
| E6-S2 | 登录态路由守卫 | 自动跳转逻辑 | P0 |
| E6-S3 | 首次使用引导 | 简单的 onboarding 提示 | P2 |
| E6-S4 | 空状态设计 | 没有交易计划时的引导 | P1 |

## 执行建议

### 第一阶段：跑通链路（Epic 0-2）
目标：能登录，能操作飞书文档
预期产出：一个能创建周报文档的空壳应用

### 第二阶段：核心功能（Epic 3-4）
目标：完整的计划-执行-复盘流程
预期产出：可以自己用起来的 MVP

### 第三阶段：打磨体验（Epic 5-6）
目标：统计、总结、引导
预期产出：可以给小圈子用的版本
